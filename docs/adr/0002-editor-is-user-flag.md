# Editor is a flag on User

Song/Artist mutate rights are a boolean **`isEditor`** on the Auth.js/Prisma `User` row — not an env email list, not an Editor/Role table. Any Google account may sign in; only `isEditor` may create/edit Songs and Artists. Flip `isEditor` in the database (no promote UI). Privileged procedures and editor UI re-check the flag so a demotion applies without waiting for re-login. Non-Editors get the same library experience as anonymous users. Programs stay outside this flag (see ADR 0001).

**Admin** is a separate boolean **`isAdmin`** on the same User row, the same shape as Editor. It does not grant Song or Artist editing. An Admin may open a page that lists every User who has signed in with Google (name, email, and whether they are an Editor). Anyone else is turned away, and the link is shown only to Admins. The one-time data change set `isAdmin` on the User who was already an Editor, so that account is the only Admin. Accounts that have never signed in are not listed, and there is no invite-by-email. Granting or revoking Editor from the site stays out of scope — the no-promote-UI line stays until that ticket. Admin stays a flag on User, not a role table.
