# PRD: Alvo Cifras (v1)

Build-ready product spec for **Alvo Cifras**: one public web app with the Song library (cifras + letras) and the Program/slides builder sharing that library. Anyone can browse Songs and assemble/export Programs; only Editors create or edit Songs and Artists.

Implementation can start from this document without reopening product scope. Do not treat fog items as blockers.

**Glossary:** [`CONTEXT.md`](../../CONTEXT.md) — use those terms; do not invent synonyms.  
**Decisions:** [`docs/adr/`](../adr/)  
**Import:** [`docs/research/livrinho-import.md`](../research/livrinho-import.md)  
**Public IA prototype (throwaway):** branch [`prototype/public-ia`](https://github.com/mmdfmateus/alvo-songs/tree/prototype/public-ia) — Variant C.  
**Source map:** [#1 Alvo Cifras spec](https://github.com/mmdfmateus/alvo-songs/issues/1)

Canonical terms are **English** (code/data). User-facing copy is **PT-BR**.

## 1. Destination

A new app on this repo (`alvo-songs`), not a rewrite of `alvocifras` or `programa-slides-builder` (those are reference only).

- Public **Biblioteca**: browse Songs and Artists; open a Song and read Cifra / Letra (mobile-friendly).
- Public **Slides**: assemble a Program, share a view link, Export a projection PDF.
- **Editors** (Google users with `User.isEditor`): create/edit Songs and Artists, including Cifra paste and Trechos.
- Initial catalog: COMU *Livrinho de cifras* markdown. Do **not** migrate the alvocifras MySQL DB.

## 2. Users & access

| Who | What they can do |
| --- | --- |
| Anonymous | Browse Biblioteca; view a Song; create/view/Export Programs; edit/delete a Program only from the browser that created it (ownership cookie). |
| Signed-in Google, not Editor | Same library experience as anonymous. Sign-in does not grant Song/Artist mutate or Program powers. |
| Editor | Everything anonymous can do, plus create/edit Songs and Artists. No extra Program powers ([ADR 0001](../adr/0001-program-link-only-cookie-ownership.md), [ADR 0002](../adr/0002-editor-is-user-flag.md)). |

- Any Google account may sign in. `isEditor` is a boolean on `User`, flipped in the DB for v1 (no promote UI). Mutate procedures re-check the flag so a demotion applies without re-login.
- Programs are **not** gated on login and are **not** an Editor privilege.

## 3. Goals (v1)

- Ship Biblioteca + Slides as one app with one Song listing.
- Seed the library from the livrinho (Cifra JSON + initial Trechos); Editors clean flagged rows.
- Song page: title, optional Artist, Cifra tab, Letra tab, optional YouTube (`videoId`), optional Artist image. **No transpose.** Cifra/Letra reading must work well on mobile.
- Program builder keeps Programa Slides **section types** and **slide expansion** rules, with the Song behind a song section being the shared richer Song (live title + Trechos at preview/Export).
- Export a 16:9 projection PDF. The PDF is the only snapshot; the Program stays live ([ADR 0004](../adr/0004-live-song-section-export.md)).

## 4. Non-goals (v1)

See also §15. Explicitly out of this product:

- Scaffolding choices beyond the stack in §12 (this spec does not pick shadcn vs other UI kits).
- Transpose, Playlists, Roles/orgs/multi-tenant churches.
- Migrating alvocifras MySQL data or rewriting the old apps in place.
- Canva Connect, PPTX, Recados image management inside the app, game logic/timers.
- A public Program gallery; portable Program edit links; Program recovery if the ownership cookie is lost.
- Rebuild-from-Letra / auto-sync Trechos after a later Cifra save ([ADR 0005](../adr/0005-trechos-independent-of-cifra-edit.md)).
- Snapshot-on-add or in-app pin/freeze of Song sections ([ADR 0004](../adr/0004-live-song-section-export.md)).
- Editor promote UI; env-var email allowlist as the source of truth ([ADR 0002](../adr/0002-editor-is-user-flag.md)).

## 5. Information architecture

**Winner:** prototype Variant C — sticky Alvo-style header with mode pills **Biblioteca | Slides** ([ADR 0006](../adr/0006-public-ia-biblioteca-slides.md)).

- Song browse mirrors Alvo: search, **Músicas** / **Artistas**.
- Builder product area is labeled **Slides** (not Programas). Domain entity remains **Program**.
- Left mode rail and CifraClub-first browse are rejected as the starting shell.
- HTML prototype stays throwaway; do not merge `prototypes/public-ia` to `master`.

### Routes (Variant C)

| Path | Surface |
| --- | --- |
| `/` | Biblioteca home (search + Músicas / Artistas entry) |
| `/musicas` | A–Z Song list |
| `/musicas/[id]` | Song page: title, optional Artist, **Cifra \| Letra**, **Escutar** (YouTube if `videoId`) |
| `/musicas/nova`, `/musicas/[id]/editar` | Editor only: Cifra paste + preview, Trechos, metadata |
| `/artistas`, `/artistas/[id]` | Artist directory / Artist + Songs |
| `/artistas/novo`, `/artistas/[id]/editar` | Editor only |
| `/slides` | Meus slides (this device; localStorage, not a DB query) |
| `/slides/[id]` | Public view + Exportar (read-only Program UI) |
| `/slides/[id]/editar` | Cookie owner only — not a portable secret link |

Exact path strings may follow T3 App Router conventions; the `/slides…` prefix and the Biblioteca labels above are locked.

## 6. Biblioteca

### Public

- Anyone can search and browse Songs and Artists.
- Song page v1: title, optional Artist (name + image if present), Cifra tab, Letra tab, optional YouTube. No transpose.
- Letra is **derived** from Cifra at read time (`ChordLyricsPair.lyrics`). It is not stored.
- Cifra/Letra reading must be **mobile-friendly** (must, not fog).

### Editors

- Create/edit/delete Songs and Artists.
- Song fields: `title`, required `cifra`, optional `artistId`, optional `videoId`, ordered Trechos.
- Artist fields: unique case-insensitive `name`, optional `imageUrl`. Upload **provider** is fog (§14); storing a URL is enough for v1.
- Non-Editors who sign in see the same library UI as anonymous users (no editor chrome).

## 7. Cifra, Letra, and Trechos

### Stored Cifra

Persist ChordSheetJS `ChordSheetSerializer` output as Prisma `Json` — the **object**, not a double-encoded string, not nullable (empty `chordSheet` is fine). Pin **chordsheetjs@7.17.0** (same major the import research used). Do not store a second original paste or a Letra column.

### Editor input ([#4](https://github.com/mmdfmateus/alvo-songs/issues/4))

- Editors paste/edit **chords-over-words only** (livrinho / cifra-site dialect: chord-above-lyric, parenthetical progressions, `Intr:` lines, messy spacing). Not ChordPro, not dual-format.
- Live preview of the parsed Cifra (`ChordsOverWordsParser` + formatter), same idea as Alvo Cifras today: textarea + preview until it looks right.
- Paste is a way in only. Re-edit **reconstructs** chords-over-words from the stored Cifra.

### Trechos ([ADR 0005](../adr/0005-trechos-independent-of-cifra-edit.md))

- Seeded from Letra **only once** — on Song create or import.
- After that, saving a new Cifra **leaves Trechos unchanged**. No auto-sync, no rebuild-from-Letra action, no save-time notice.
- Editors reshape Trechos only by hand (ordered list: add / remove / reorder / edit text). Empty `text` is allowed; zero chunks are allowed.
- Trecho edits never write back into the Cifra.
- Empty Trechos stay empty until an Editor adds them.

## 8. Slides (Programs)

[ADR 0001](../adr/0001-program-link-only-cookie-ownership.md).

- Unlisted: no site-wide gallery. Share the view URL only.
- On explicit create, the creating browser gets a **long-lived ownership cookie**. DB stores `ownerTokenHash` only (secret stays in the cookie).
- Meus slides = device-local list (localStorage), not a query of all Programs.
- View URL: read-only Program UI + Export. Cookie owner may edit/delete via `/slides/[id]/editar`.
- No portable edit link. If the cookie is lost, that Program stays view/export-only.
- Editors get no special Program powers. Assemble/export stay login-free.

### Section types

Same types as Programa Slides. Data values English; UI labels PT-BR (not frozen):

| `type` | UI | v1 `payload` ([ADR 0007](../adr/0007-prisma-data-model.md)) |
| --- | --- | --- |
| `opening` | Abertura | `{ communityName, subtitle? }` |
| `song` | Música | `{}` — live `songId` is the column (nullable even when type is song) |
| `announcements` | Recados | `{ title }` |
| `game` | Brincadeira | `{ title }` — **no** game `label` in v1 |
| `moment` | Momento | `{ title }` |

Blank count is an **app constant of 1**, not stored. Default opening `communityName` may stay `COMU JOVEM` (the community this app serves).

Builder is assemble-only: add / reorder / remove sections; pickers and short fields; no lyric editing, rich text, or slide WYSIWYG inside the Program.

## 9. Export

### Live library ([ADR 0004](../adr/0004-live-song-section-export.md))

Preview and Export both read the current library **title** and **Trechos**. Song section stores only a live `songId` (no FK — dangling id is the broken-ref state).

| Situation | Behavior |
| --- | --- |
| Song missing | That section contributes **no slides**; edit UI and public view show a **broken reference** |
| Song has zero Trechos | **Title slide only** |
| Editors change the library | Program owners are **not** notified |
| Downloaded PDF | Only point-in-time copy; Program stays live |

### Slide expansion (keep Programa Slides rules, adjusted for v1 payload)

| Section | Slides |
| --- | --- |
| Opening | Brand opening: `communityName` + optional subtitle |
| Song (resolved) | Title-chip (current title) + one lyric Slide per Trecho |
| Song (missing) | None |
| Announcements | Title-chip (`title` or “Recados”) + exactly 1 blank |
| Game | Title-chip (`title` or “Brincadeira”) + exactly 1 blank (no extra label slide) |
| Moment | Title-chip (`title` or “Momento”) |

Slide kinds: `opening` | `titleChip` | `lyric` | `blank`.

### PDF mechanics

Keep Programa Slides export mechanics:

- Generator: **`@react-pdf/renderer`** (no Chromium for v1). Server or client render is OK; watch Vercel ~4.5 MB function body (stream/Blob if needed).
- Canvas: **16:9**, `960×540` pt, one page per Slide.
- Layouts: opening, title-chip, lyric (centered, ~4–6 lines/chunk, no repeated song title on lyric slides), blank (empty field for later Canva fill-in).
- Short hint near Export: after download, upload the PDF in Canva (desktop) to drop images on blanks / share / store. **Not** Canva Connect.

**Visual identity** (COMU JOVEM orange/purple vs Alvo-branded) is fog. Implementers may copy the existing COMU theme from `programa-slides-builder` as a stand-in; do not block on a rebrand.

## 10. Initial catalog

One-shot seed from `programa-slides-builder/data/sources/livrinho-de-cifras.md`. Full pipeline and failure modes: [`docs/research/livrinho-import.md`](../research/livrinho-import.md).

Do **not** import `song-library-seed.json` as-is (it was chunked from chord-stripped booklet text, not Letra-of-Cifra). Do **not** migrate alvocifras MySQL.

```
livrinho-de-cifras.md
  → split titles (TITLE_RE + TITLE_RE2 + unbolded `N- Title`)
  → booklet cleanup
  → try ChordsOverWordsParser, else ChordSheetParser({ song: new Song() })
  → persist ChordSheetSerializer JSON as Cifra
  → Letra = ChordLyricsPair.lyrics (display/seed only)
  → initial Trechos = seed paragraph + ~4-line fallback chunker(Letra)
  → Artist unset
  → Editor review flagged rows (fallback parse, 0-chord, leftover markdown, swallowed “Convite à Liberdade”)
```

Custom code is for split / cleanup / `is_chord_line`-style filtering — not a parallel Cifra format. Interactive Editor after import stays COW + live preview (§7).

Existing Programs in the slides Neon DB: **fog** — v1 may start with an empty Program table.

## 11. Data model

Implement the canonical Prisma sketch in [ADR 0007](../adr/0007-prisma-data-model.md) **without inventing columns**.

Summary:

- Neon Postgres, `provider = "postgresql"`, `citext` enabled ([ADR 0003](../adr/0003-prisma-neon-postgres.md)).
- Auth.js adapter tables (`User` / `Account` / `Session` / `VerificationToken`, cuid ids) + `User.isEditor Boolean @default(false)`. No Program↔User FK.
- Domain ids: **uuid**. Program uuid is the public view URL.
- `Artist.name` unique case-insensitively; delete **SetNulls** `Song.artistId`.
- `Song.cifra` required Json; no `lyrics`, no `sourceNumber`, no Playlist.
- `LyricChunk`: `songId`, `position`, `text`; unique `(songId, position)`; Song delete **cascades** Trechos.
- `Program.ownerTokenHash` unique. Program delete **cascades** Sections.
- `Section.songId` has **no FK**. `type` is a string, not a Postgres enum. `payload` defaults `{}`.

Local dev: Docker Postgres or a Neon branch — same engine, not SQLite, not the slides PGlite/Drizzle stack.

## 13. Acceptance criteria (implementation round)

- [ ] Public Biblioteca: search, Músicas list, Artistas list/detail, Song page with Cifra | Letra | optional Escutar — usable on mobile.
- [ ] Sticky header with Biblioteca \| Slides pills; Slides routes under `/slides…`.
- [ ] Editors (DB-flipped `isEditor`) can CRUD Songs/Artists; non-Editors and anonymous cannot mutate the library.
- [ ] Cifra editor: chords-over-words + live preview; re-edit reconstructs from stored serializer JSON; Letra is derived, not stored.
- [ ] Trechos seed once on create/import; later Cifra saves do not change them; Trechos are hand-editable.
- [ ] Livrinho seed loads ~110 Songs with Cifra + Trechos; flagged rows are reviewable; no alvocifras DB migration.
- [ ] Anyone can create a Program without login; Meus slides is device-local; view URL is read-only + Export; only the ownership cookie can edit/delete.
- [ ] Section types opening / song / announcements / game / moment with v1 payloads; blank count = 1; no game label slide.
- [ ] Song section preview/Export uses live library title + Trechos; missing Song → no slides + broken-ref UI; zero Trechos → title slide only.
- [ ] Export downloads a 16:9 PDF via `@react-pdf/renderer`; Canva upload hint present; no Canva Connect.
- [ ] Schema matches ADR 0007 on Neon Postgres; Auth.js + `isEditor`; `Section.songId` is not a FK.
- [ ] UI copy is PT-BR; glossary terms from `CONTEXT.md` are not renamed.

## 14. Fog (not blocking v1)

Decide later only if they come up during implementation:

- PDF visual identity (keep COMU JOVEM theme vs Alvo-branded slides) — COMU stand-in is OK.
- Artist image upload provider (UploadThing vs Vercel Blob vs other) — URL field is enough.
- Abuse / rate limits on public Program create.
- Custom domain.
- Mobile vs desktop priority for the **Slides builder** (Cifra reading is already a mobile must).
- Import existing Programs from programa-slides-builder Neon vs start empty.
- Artist directory UX when most livrinho Songs have no Artist.

## 15. Out of scope

- Building beyond this spec’s product surface in the wayfinder map itself (map is done).
- Migrating alvocifras MySQL data.
- Transpose; Playlists (schema-only in alvocifras, never shipped).
- Rewriting alvocifras or programa-slides-builder in place.
- Canva Connect, PPTX, Recados image management, game logic/timers.
- Roles, orgs, or multi-tenant churches beyond the Editor flag.
- Gating Programs behind login; a public Program gallery; portable edit links.
